# ADR 009: 戻る・進むはツールバーの明示ボタンにする

## Status

Accepted (2026-07-26)

## Context

[ADR 008](008-tab-identity-and-history.md) でタブ内履歴を導入し、戻る操作を
5 経路 (ESC / Backspace / 横スワイプ / マウス戻る / システム戻る) に統一した。
残っていた課題が 2 つ:

1. **進む (forward)**: `GalleryTab.forward()` は実装・テスト済みだが、割り当てる
   入力が無く未配線のまま
2. **履歴ジャンプ**: 「戻るボタン長押しで履歴一覧」を構想していた

これらをジェスチャや長押しに割り当てる前提が、Android 15 で崩れた:

- **戻るボタンが存在しない**。ナビゲーションはジェスチャのみで、
  「戻るボタンの長押し」は原理的に不可能
- **画面端は OS のものになった**。エッジスワイプは predictive back
  (辺が波打つプレビューアニメーション付きの戻り) に取られていて、
  アプリが左右エッジに独自ジェスチャを置く余地がない
- アプリ内履歴を歩くために `PopScope` で戻りを横取りすると、predictive back の
  プレビューは表示されない。これはアプリ内ナビゲーションを持つアプリ共通の
  トレードオフ (Chrome も同じ) で、受け入れる

## Decision

**ブラウザと同じく、ナビゲーションは画面上の明示的な UI にする。**
ギャラリーのヘッダーを 2 行構成にする:

```
1 行目:  [タブ][タブ][タブ]…  [+]          ← 既存のタブストリップ
2 行目:  ←  →  [ 場所の表示 / 検索 ]  ☰    ← 新設のツールバー
```

- **← / →** はアクティブタブの履歴を歩く。無効状態 (先頭 / 末尾) は灰色
- **場所の窓**はアドレスバーと検索窓を兼ねる (詳細は
  [design.md](../virtualized_gallery/design.md) のツールバー節)
- **☰** は「今のタブの中の行き先 + アプリ操作」。Pixiv ならセクション
  (トップ / ブックマーク) が上段に載り、下段に再読み込み・設定。
  `+` は「新しいタブを開く」専用のまま
- **両行ともスクロールで隠れ、上スクロールで戻る**。タブレット横画面では
  サムネイル 2.7 行分しか見えておらず、常設 2 行は許容できないため
- システム戻る (ジェスチャ) の意味は変えない: 履歴を 1 つ戻る、
  先頭ならタブを閉じる ([ADR 008 追記](008-tab-identity-and-history.md))。
  ツールバーの ← はそれと同じ操作の可視化であって、別の操作ではない

### 採らなかった案

- **エッジスワイプで進む/戻る**: OS が画面端を所有するため成立しない (上記)
- **戻る長押しで履歴一覧**: 長押しする対象のボタンが無い。履歴一覧は将来
  ← の長押し (ツールバー上のボタンなら長押しできる) か ☰ 内に置ける。
  今回は配線しない
- **Chrome の N 窓 (タブ数ボタン)**: スマホ版 Chrome にあるのはタブストリップが
  無いからで、ストリップがある本アプリでは役割が被る。ストリップが溢れて
  一覧性が落ちてから検討する

## Consequences

- **Good**: 進むがようやく家を得る。プラットフォーム差 (Android 15 に戻るボタンが
  無い、iOS にジェスチャの流儀がある) に依存しない、常に見えて説明不要のナビになる
- **Good**: アドレスバーの導入で「リンクからタブを作る」(ADR 008 の構想) が完成する
- **Bad**: 縦 48dp 程度を消費する。スクロール自動隠しで緩和するが、
  隠れている間は ← → も使えない (システム戻るは常に効くので致命ではない)
- **Note**: ビューアと動画プレーヤーは従来どおり Navigator のルート
  (ADR 008 のスコープ外) なので、このツールバーはビューア内には出ない
