# ADR 010: ビューアをタブの中の場所にする

## Status

Accepted (2026-07-26)。実装は段階的、未着手。

## Context

[ADR 008](008-tab-identity-and-history.md) でタブと履歴を、
[ADR 009](009-navigation-toolbar.md) でナビゲーションツールバーを入れた。
ビューアと動画プレーヤーだけが `Navigator` のルートのまま残っている
(ADR 008 が明示的にスコープ外としていた)。

フェーズ 2C を終えた時点で、残っている重複はここに集中している:

| | 行数 |
|---|---|
| `lib/screens/viewer/viewer_screen.dart` | 1081 |
| `lib/screens/video/video_player_screen.dart` | 147 |
| ギャラリーのボディ 3 つ (SMB / お気に入り / Pixiv) の合計 | 597 |

ボディ側はもう小さく、残る差も本物 (SMB はディレクトリと長押し、Pixiv は検索と
作者、お気に入りは未接続アイコン)。**質量と重複はビューアにある。**

ビューアがルートであるために自前で持っているもの:

| ビューアが持っているもの | 既にある仕組み |
|---|---|
| アイテム列 + 現在位置 + 先読み | `GallerySession` の `loaded` + `anchor` + `ThumbnailLoader` |
| `Navigator.pop` に `{'action': 'showUser', ...}` を載せて呼び出し元に解釈させる | タブの履歴と `navigate` |
| `onOpenAuthorInNewTab` / `onOpenTagSearchInNewTab` | `onOpenInNewTab` |
| 3 つのボディがそれぞれ `ViewerScreen(...)` を組み立てる (結合 20 箇所) | URI からボディが選ばれる仕組み |

pop に Map を載せて返すのは、**ビューアがタブの外にいることだけが理由**で存在する
独自プロトコルで、タブになれば丸ごと消える。

もう 1 つ、期限付きの負債がある。2C-3 で Pixiv の検索欄を撤去したとき、
**作品 URL の貼り付け** (`pixiv.net/artworks/<id>` でビューアを直接開く) を移し先が
無いという理由で落とした。繋ぎを作らなかったのは、ビューアが場所になれば
`pixiv://default/artworks/<id>` が成立して**ただで戻ってくる**から
([design.md 節 7 残る検討](../virtualized_gallery/design.md))。

## Decision

### 1. ビューアは場所である

```
pixiv://default/artworks/456           1 つの作品
smb://1700000000000/books/vol2/a.jpg   1 枚の画像
smb://1700000000000/books/作品集第2巻.pdf   1 冊
smb://1700000000000/books/vol2/        フォルダ (末尾の / が「リスト」の印)
```

**SMB は末尾のスラッシュでリストとアイテムを区別する。** 名前では区別できない —
フォルダに `test.jpg` という名前を付けられるので、拡張子で当てると一覧の代わりに
ビューアが開く (2026-07-26 に実際に踏んだ)。サーバーに聞けば確実だが、
`dart_smb2` に単体の stat が無く親を一覧する往復が要るうえ、**ボディの選択が
非同期になり**、「復元したタブは接続前に自分が何者か言える」という前提も壊れる。

アドレスを組み立てるのは常にアプリ自身で、そのときは一覧が `isDirectory` を
教えてくれている。**知っている側が書き込む**のが筋で、後から推測しない。
外から来て印が落ちたアドレスだけ、開ける拡張子かどうかで最善を尽くす。

タブのボディが URI の scheme で選ばれる仕組みはそのまま。ビューアはルートではなく
**タブの中身**になるので、タブストリップとツールバーはその上に居続ける。

### 2. 前後の作品は「履歴の直前」から取る。ただし自分を含むときだけ

スワイプで隣の作品へ行くには「どのリストの何番目か」が要る。**URI には埋めない。**
ビューアは必ずリストから開かれるので、**タブ履歴の直前のエントリがそのリスト**
だから。

判定は「履歴があるか」ではなく **「直前のセッションの表示リストにこのアイテムが
いるか」**。SMB のフォルダを見ているタブに `pixiv://default/artworks/456` を
貼ったとき、直前は無関係なフォルダで、そこを周辺リストとして扱ってはいけない。

URI からアイテム id を出す規則はソースごとに違うので、**dialect に `itemIdOf(uri)`
を足す** (`describe` / `knows` / `search` と同じ列)。保存するデータは増えない。
コストは開くときに 1 回の走査で、前後移動に必要な index も同じ走査で取れる。

| 状況 | 結果 |
|---|---|
| 一覧から開いた | 前後あり |
| アドレスを貼って新しいタブで開いた | **1 枚モード** (前後なし) |
| 直前が無関係な場所 | 1 枚モード |
| 直前が未読 (復元直後) | **読んでから判定する** |

最後の行が要る。復元したタブは `[一覧, 作品]` の形で戻るが一覧の中身は空なので、
「見つからない = 1 枚」で倒すと**復元後だけ前後移動できないアプリ**になる。
実際の読み込みは永続化の lazy load と同じ経路になる見込み。

### 3. スワイプは履歴を積まない

積むと 2 の前提が崩れる。1 枚めくるたびに「直前 = 前の作品」になってリストが
見えなくなり、40 枚めくった後の戻るが 40 回になる。

**アイテムを跨ぐときは `replaceCurrent`。** 履歴は `[一覧, 作品]` のままで、
アドレスバーは今の作品を映し、コピーすれば今見ているものが取れ、戻るは一覧へ。
ADR 008 の「移動でないものは replaceCurrent」(再読み込み・フィルタ変更) と同じ扱い。

言い換えると **タブがいるのは「一覧」で、ビューアのエントリはその中の位置を指す栞**。

### 4. アドレスは作品を指す。その中のどこにいるかは見え方の状態

現行のビューアは**ページ送りが作品の境界を越えて次の作品へ転がる** 1 本の軸に
なっている (`_nextPage` が最終ページで `_nextItem` を呼ぶ)。この読み味は保つ。

すると「何ページ目か」は作品の中の位置であって、行き先ではない:

| 見ているもの | アドレス | 見え方の状態 (セッションが持つ) |
|---|---|---|
| 1 枚の画像 | その画像 | 拡大率・位置 |
| 複数ページの作品 / ZIP / PDF | その作品・そのファイル | **何ページ目か** |
| 動画 | そのファイル | **再生位置** |

3 つとも同じ形 — **アイテムがアドレス、その中のどこにいるかはセッションの状態**。
`anchor` (一覧のスクロール位置) と同じ棚に載る。

アドレスが変わるのは**アイテムの境界を越えたときだけ**で、ページをめくった
だけでは変わらない。

#### 4-1. その状態は `ViewerMark` として持つ (2026-07-26 実装)

上の表の「見え方の状態」は段階 1〜6 の時点ではビューアのウィジェット状態のまま
だった。タブを切り替えるとアクティブなタブのボディしか作らないので、**戻ると
ZIP は 1 ページ目に、動画は先頭に戻っていた**。`GallerySession.mark`
(`ViewerMark`) に上げて解消した。`anchor` と同じ棚に載る、という 4 の結論の実装。

決めたこと 3 つ:

- **「止まっている」は位置とは別に持つ**。位置だけなら「ここから始めよ」の意味に
  なり、将来の `?t=30` はそれを期待する。「かつ始めるな」は別の情報
- **タブを離れるときは、再生中だったかに関わらず停止で書く**。タブは何時間後に
  戻ってくるか分からない場所で、音が勝手に鳴り出すことは決して意図ではない。
  スワイプはこの経路を通らない (画面が生きたまま `didUpdateWidget` で移る) ので、
  6 の「直前がしていたことを続ける」はそのまま残る
- **総再生時間も一緒に覚える**。復帰時に「どこで止まっているか」をバーで見せるが、
  そのためにプレイヤーを開くと、タブを覗くたびに共有への接続とデコードが走る

帰結として、マークは**履歴エントリと寿命を共にする**。タブ切り替えでは残り、
一覧に戻ってから同じ動画を開き直すと `navigate` で新しいエントリになるので
頭から。→ (forward) で戻れば続きから。使ってみて自然だったのでこれを採る。

### 5. ZIP と PDF はアイテムであって場所ではない

フォルダのメンバーは別々の作品だが、**ZIP の中身は 1 つの作品の中の位置**。
棚と本の違いで、本のページは行き先ではない。現行実装 (ビューアが `resolvePages`
で展開する) がすでにそうなっており、4 の表とも整合する。

### 6. 表示フィルタをセッションへ上げる

3+ で絞った一覧からビューアに入ったとき、**絞って隠したはずの作品にスワイプで
行けてしまう**。今は絞り込みが Pixiv ボディの `_visibleItems` にあり、ビューアは
それを引数で受け取っている。ビューアがセッションからリストを読む以上、絞り込みも
セッション側に無いと辻褄が合わない。

`minPageCount` は 2C-4 でセッションに移してあるので、`session.visibleItems` を
作れば済む。ボディからまた 1 つ重複が消える。

### 7. フルスクリーン (没入モード)

**タップ、または 3 秒放置で、アプリのヘッダー 2 段とシステムバーの両方を隠す。**
ヘッダーの出し入れという機能はタブである以上あるが、2C-5 のスクロール判定
(`ChromeScrollRule`) はビューアでは走らせない — スクロールしないので。

**ビューアは自前のナビゲーションを持たない。** 元は絵の上に
「← タイトル (1/18) ☰」の行があったが、← も場所の表示もアドレスのコピーも
**ツールバーが既に持っている**。2 つ持つと重なるうえ、ビューアだけの特別扱いが
残る — ADR 010 の狙いはその逆なので、消すのはビューア側。残ったページ位置と
キャッシュ元は下の行 (♡・DL と同じ列) へ移した。**行き先ではなく状態**だから。

ページ数フィルタは**アイテムの場所では出さない**。フィルタは一覧を絞るもので、
作品は一覧ではない。ソースにページ数の概念があるか (`hasPageCounts`) は変わら
ないので、場所の側で判断する。

**ヘッダーは絵の上に浮かせる** (Column の 1 行ではなく Stack)。
横画面だと「ステータスバー + ヘッダー 2 行」で 3 行ぶんあり、押し下げる形だと
**タップするたびに絵が 3 行縮む** — 一覧に戻るわけでもないのに画面が跳ねるのが
気持ち悪い。ビューア自身のオーバーレイ (戻る・★・ページ数) は元々絵の上に
浮いているので、揃えると**タップでレイアウトが 1 ピクセルも動かなくなる**。
一覧側は今までどおり押し下げる (読み下すものなので、絵と違って隠れると困る)。
**ステータスバーぶんは押し下げたまま**にする — システムのもので、その下に描く
ものではない。返すのは全画面のときだけ。浮かせるヘッダーは**半透明**にする。
薄くするのはウィジェット全体ではなく**配色** (`Opacity` だと文字とアイコンまで
薄くなり、それこそが読ませたいもの)。

新しい論点がある。**システム UI の状態がアクティブなタブの場所に追従する**。
ビューアはルートではなくタブのエントリなので、「画面を抜けたら戻す」では足りず、
タブを切り替えた・戻った・タブを閉じた、のすべてでシステムバーを戻す必要がある。
**場所がグローバル状態に影響する初めてのケース**なので、実装時はここを一箇所に
まとめる。なお `SystemChrome` は現在この app のどこでも使っていない。

### 8. 動画は同じビューアの中のページ

- **同じビューア、ページごとに見せ方を選ぶ** (画像ならフォト、動画ならプレーヤー)。
  混在フォルダを 1 つのリストで送れる。現行は逆で、SMB が
  `where(isVideo != true)` で動画をビューアのリストから除外している
- **自動再生しない**。スワイプで通り過ぎるだけで音が鳴るのは困る。
  サムネイル + 再生ボタン
- **横ドラッグはビューアのもの** (次のアイテムへ)。動画のシークは**シークバー**と、
  10 秒 / 60 秒の**スキップボタンのオーバーレイ**で行う
- **今のページだけが資源を持つ**。`PageView` は隣のページも作るので、放置すると
  隣の動画が鳴り出す。ページを離れたらデコーダとプロキシ接続を解放する

## 採らなかった案

- **URI にリストを埋める** (`pixiv://default/artworks/456?from=...`)。前後移動の
  ためだけにアドレスが読めなくなる。タブ履歴が既に「どこから来たか」を持っている
  のに二重に持つことになる
- **動画を別のボディにする**。ボディは URI の scheme で選ばれるが、
  `smb://1700000000000/books/movie.mp4` と
  `smb://1700000000000/books/a.jpg` は同じ scheme。拡張子を見てボディを
  選ぶ per-item の分岐を場所のルーティングに持ち込むことになり、しかも
  **混在スワイプが原理的に不可能**になる (スワイプのたびにボディが入れ替わる)
- **ZIP / PDF を場所にする**。「棚」と「本」を同じ扱いにすることになり、
  本のページが行き先になってしまう
- **ページ番号をアドレスに載せる**。作品の中の位置は見え方の状態 (4)。
  ただし「この 1 ページを送りたい」用に `?p=` を将来足す余地は残す

## Consequences

- **Good**: 独自の pop プロトコルと `onOpen*InNewTab` が消え、行き先の指定が
  タブの仕組み 1 本になる。3 つのボディの `ViewerScreen(...)` 組み立ても消える
- **Good**: 作品 URL の貼り付けが戻る。しかも Pixiv 専用ではなく、
  SMB の 1 枚にもアドレスが付く
- **Good**: 動画と画像が 1 つのリストになり、混在フォルダを送れるようになる
- **Good**: 戻る・進む・アドレスバー・タブが、ビューアでもそのまま効く
- **Bad**: 没入モードがタブの状態に影響される (7)。場所を切り替えるたびに
  システム UI を正す必要があり、抜け漏れると「バーが消えたまま」になる
- **Bad**: 動画ページの資源管理 (8) が新しい費用。`PageView` の隣接ページと
  再生の寿命を合わせる必要がある
- **Note**: 永続化 (ADR 009 の帰結節) はこの後。ビューアが場所になると URI の
  種類が増えるので、先に永続化を作ると作り直しになる

## 段階 (2026-07-26 に 1〜6 すべて完了)

1. **ビューアの場所とボディ** — URI、`itemIdOf`、「直前が自分を含むリストなら
   前後あり」。まず Pixiv の画像だけ
2. **SMB とお気に入りを同じ経路へ** — 3 箇所の `ViewerScreen(...)` が消える
3. **pop プロトコルの撤去** — `{'action': ...}` を `tab.navigate` に
4. **フルスクリーン** — タップ / 3 秒放置、システムバー、タブ追従
5. **`visibleItems` をセッションへ** — 6 の辻褄合わせ。1 より先でもよい
   (独立して意味があり、Pixiv ボディが軽くなる)
6. **動画をリストに入れる** — 混在スワイプ、今のページだけ再生。
   実装時に決めたこと: 再生の規則は「**直前がしていたことを続ける**」
   (意図して開いた = `initState` なら再生、スワイプで来た = `didUpdateWidget`
   なら直前が再生中のときだけ)。この区別はタブの構造から**タダで**得られた —
   セッションにフラグを足す必要は無かった。
   資源の寿命も同様で、ビューアは 1 ページしか描かないので
   ページの消滅がそのまま解放になる (`PageView` の隣接ページ問題は無い)

## 残る検討

- **`?p=` / `?t=`** — 作品の中の 1 ページ、動画の 1 場面を人に送るための任意の
  クエリ。既定にはしない (4)。器は `ViewerMark` の `page` / `at` として
  存在するので、やるときは URI から `ViewerMark` を作る経路を足すだけになる (4-1)
- **ビューアに入った後で絞り込みを変えたら** — 今見ているものが隠される側に
  なる場合がある
- **復元後の lazy load** — 2 の最後の行。永続化と同じ経路になる見込みなので、
  そちらで一緒に決める
- **自動再生しない / 横ドラッグはビューアが取る (8)** は使ってみて変えうる
