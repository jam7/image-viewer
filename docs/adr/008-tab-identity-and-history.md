# 008: タブ identity をタブ ID とし、URI はタブ内ナビ履歴の要素とする

## Status

Accepted ([ADR 007](007-virtualized-gallery.md) の決定 4 を一部改訂)

## Context

[ADR 007](007-virtualized-gallery.md) の決定 4 は「**タブの識別子 = ソース URI**、同じ URI の
タブは 1 つ (重複開防止)」とした。フェーズ 1 / 2A はこの前提で実装され、`GalleryTab` は
`sourceUri` を identity として持っている。

その後、目指す姿が「**ブラウザのタブ**」であることが明確になった:

- 同じ場所を 2 つ開けてよい (複製したい、比較したい)。重複開防止はむしろ邪魔。
- リンクからタブを作れる。タブ生成は URI 駆動でありたい。
- **各タブが自分のナビ履歴を持つ**。タブ内で戻る/進むができ、戻れば元の場所が
  スクロール位置ごと復元される。

ここで ADR 007 の決定 4 と矛盾が出る。URI がタブの identity なら、①同じ URI のタブを
2 つ作れない ②タブ内で場所が変わると identity が変わってしまう。identity は
「タブという入れ物」に属し、URI は「そのタブが今いる場所」でしかない。

なお ADR 007 の他の決定 (1: セッション状態はタブ所有 / 2: ソースは無状態 `loadPage` /
3: スクロール単一トリガ / 5: メモリ方針) は有効で、本 ADR はそれらを覆さない。

## Alternatives

### A. URI identity のまま、重複開だけ許す

- タブ ID を「URI + 連番」にする程度の対症療法。タブ内で場所が変わると ID が変わる
  問題が残り、ナビ履歴を持たせられない。

### B. タブは 1 URI 固定のまま、ナビは Navigator スタックに任せる (現状の延長)

- 現在の方式。タブを跨いだ行き来ができず、「タブ A の 3 階層目」と「タブ B」を
  並行して保持できない。Navigator スタックは 1 本しかないため、複数タブと両立しない。

### C. タブ ID と URI を分離し、タブが URI 履歴スタックを持つ

- ブラウザのモデルそのもの。identity は入れ物に、URI は履歴の要素に。

## Decision

**C を採用する。**

1. **タブの identity はタブ固有 ID** (生成時に採番、以後不変)。URI は identity ではなく
   「そのタブが今見ている場所」を表す属性に降格する。**同じ URI のタブを複数開いてよい**
   (ADR 007 の「重複開防止」は撤回)。
2. **タブは閲覧場所の履歴スタックを持つ**。ADR 007 で `GalleryTab` が所有すると決めた
   セッション状態 (`loaded` / `nextCursor` / `scrollOffset` / `ThumbnailLoader` / `sourceUri`)
   は、履歴の 1 要素 = **`GallerySession`** が持つ。`GalleryTab` はその履歴と現在位置を持つ。

   ```
   GalleryTab     { id, List<GallerySession> history, int index }
   GallerySession { sourceUri, loaded, nextCursor, scrollOffset, thumbnails }
   ```

   現 `GalleryTab` (フェーズ 1/2A で実装済) が実体として `GallerySession` なので、
   リネームして名前を新しい器に譲る。ADR 007 が「閲覧セッション」と呼んでいたものと
   同じ語。
3. **ナビゲーションはタブ内で完結**する。ギャラリー間の移動 (SMB のディレクトリ移動、
   Pixiv のセクション・検索・作者遷移) は `Navigator.push` ではなく
   `tab.navigate(uri)` で履歴に積む。戻る操作 (ESC / Backspace / 戻るボタン / 横スワイプ)
   は履歴を 1 つ戻し、**履歴の先頭で戻るとギャラリー画面自体を pop** する。
   履歴の途中から `navigate` すると、ブラウザ同様それより先の履歴は破棄する。
4. **戻ったとき再取得しない**。履歴に残る `GallerySession` は `loaded` と `nextCursor` を
   保持するので、戻ると元のアイテム列・スクロール位置がそのまま復元される。これが
   1 URI 固定タブ (代替案 B) との実質的な差。
5. **メモリ** (ADR 007 決定 5 の拡張): デコード済みサムネ (L1) を保持するのは
   **アクティブタブの現在セッションだけ**。同一タブの履歴内の他セッション、および
   非アクティブタブのセッションは L1 を解放し、`loaded` (軽いメタ列) だけ残す。
   復帰時は L2 から再表示する。履歴長のハード上限は当面設けない。
6. **タブの複製**は履歴 (URI 列と現在位置) をコピーして新 ID のタブを作る。セッション
   実体はコピーせず、表示されたタイミングで現在位置ぶんだけ読み込む。

ビューア (`ViewerScreen`) と動画プレーヤーは従来どおり `Navigator` のルートのままとし、
タブ内履歴には積まない (本 ADR の範囲外)。

## Consequences

- **Good**: 同じ場所を複数タブで開ける。リンク/複製からのタブ生成が自然に書ける。
- **Good**: タブごとに独立した戻る操作。戻ってもアイテム列とスクロール位置が生き残る。
- **Good**: identity が不変なので、タブ集合の保持・並べ替え・復元がしやすい。
- **Bad/リスク**: 戻る操作の意味が変わる (Navigator の pop → タブ履歴の pop)。ESC /
  Backspace / 戻るボタン / 横スワイプの characterization テストが効くのは「履歴の先頭で
  画面を pop する」ケースだけなので、履歴あり時の挙動には新しいテストが要る。
- **Bad/リスク**: 履歴に残るセッションぶんメモリを使う。決定 5 の L1 解放が前提。
- **Note**: ADR 007 の URI 体系 (`smb://`, `pixiv://…`, `fav://`, `dl://`) とキャッシュキー
  (`thumb:<uri>` / `full:<uri>`) はそのまま有効。変わるのは「URI がタブの identity か」
  だけで、URI 自体の役割 (場所の表現・キャッシュキー・復元キー) は変わらない。
