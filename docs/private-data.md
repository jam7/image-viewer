# 実データを公開しないための仕組み

このリポジトリは GitHub 上で public。一方、開発に使っている実データ (共有フォルダの
構成、購入した作品名、サーバーの設定 ID、実機ログ) は公開したくない。

CLAUDE.md に「書かない」と書くだけでは**繰り返し漏れた**。原因は、テストデータを書く
ときに直前まで実機ログで見ていた文字列をそのまま写すのが一番「それらしい」からで、
禁止事項は思い出したときにしか効かない。そこで規約ではなく**ゲート**にした。

## 中身

| ファイル | 役割 | 公開 |
|---|---|---|
| `tools/check-private.py` | 検査本体 | 公開 |
| `tools/test-vocabulary.txt` | テストデータに使ってよい語彙 | 公開 |
| `.githooks/pre-commit` | commit する差分を検査 | 公開 |
| `.githooks/pre-push` | push する全リビジョンとメッセージを検査 | 公開 |
| `notes/private-patterns.txt` | 実在の固有名詞の完全一致リスト | **非公開** |

**denylist を公開リポジトリに置かないこと。**「漏らしてはいけない文字列の一覧」
そのものが最も漏らしてはいけない。`notes/` (非公開の別リポジトリ、gitignore 済み) に
置き、検査は「あれば読む、無ければ構造チェックだけ」で動く。

## 有効化

```bash
git config core.hooksPath .githooks
```

clone ごとに 1 回必要 (git はフックを clone で共有しない)。

## 2 種類の検査

**構造チェック** — どこに出ても間違っているもの。絶対ホームパス、プライベート IP、
12 桁以上の数字列 (SMB の設定 ID は作成時刻ベースの 13 桁)。

**語彙チェック (本命)** — `test/` と `docs/` では、内容らしきもの (区切り文字を含む
パス、メディア拡張子のファイル名、CJK 文字列) は `tools/test-vocabulary.txt` に
載っている語からしか作れない。

語彙方式が肝心なのは**未知のデータを捕まえられる**から。denylist は「誰かが載せると
思いついた名前」しか止められないが、実際に漏れるのは誰も知らない作品名の方だった。

## 新しいテストデータが要るとき

**架空の名前を考えて `tools/test-vocabulary.txt` に足す。** これは想定された運用で、
面倒でもなんでもない。禁止されているのは、実機ログから文字列を写すこと。写したく
なったら、それは語彙に 1 行足すべきというサイン。宣言する行為そのものがレビューになる。

## 漏れを見つけたとき

未 push なら履歴から消せる。**push 前が最後の、そして唯一まともに直せるタイミング。**

```bash
python3 tools/check-private.py --all-history   # 全履歴を監査
python3 tools/check-private.py --worktree      # 手元のファイルだけ
```

未 push の範囲を書き換える手順は `git filter-branch --tree-filter` で文字列置換し、
メッセージ側も `--msg-filter` で置換する。置換後は全リビジョンを走査して再確認する
(1 度で消えたと思い込まない。実際、最初の置換ではパターンの取りこぼしと
コミットメッセージ側の残りがあった)。

既に push 済みのものは、public repo の履歴書き換え = force push になる。価値と
コストを比べて判断する。パスを伴わない設定 ID 程度なら、以後を直すだけで足りる。
